### 一、GitHub(5%)

1. GitHub有什麼基本功能和用途？
   Ans:程式碼託管（Repository）： 在雲端儲存專案檔案與原始碼，支援公開（Public）與私人（Private）儲存庫。

版本追蹤與差異比對（Diff / Commit History）： 記錄每次修改的時間、作者與變更內容，方便隨時回溯。

分支與合併（Branch & Pull Request, PR）： 允許在不同分支開發新功能或修 Bug，透過 PR 進行程式碼審查（Code Review）後再合併至主線。

協作與議題管理（Issues / Projects / Actions）： 用於追蹤待辦事項、回報問題、專案看板管理，以及透過 GitHub Actions 自動化建置與部署。

2. GitHub的版本控制如何操作？

   Ans: 建立與取得儲存庫： 在 GitHub 建立新 Repository，使用 git clone <網址> 下載到本地，或在本地專案執行 git init 並用 git remote add origin <網址> 連結遠端。

建立分支（選用）： 使用 git checkout -b feature/page 或 git switch -c feature/page 開啟新分支進行修改，避免直接改壞主分支（main）。

暫存變更： 修改檔案後，執行 git add .（或指定檔名）將變更加入暫存區（Staging Area）。

提交版本： 執行 git commit -m "描述本次修改內容"，產生一筆具有唯一雜湊值（Hash）的版本紀錄。

推送至遠端： 執行 git push -u origin <分支名稱> 將本地提交同步上傳到 GitHub。

合併與回溯： 在 GitHub 發起 Pull Request 合併分支；若需還原或查看歷程，可使用 git log 查看紀錄，或使用 git revert / git checkout 回復版本。

1. GitHub如何做到獨立網址發佈？
   Ans:透過 GitHub Pages 可將儲存庫中的靜態網頁（HTML、CSS、JavaScript 等）發佈為獨立網址（預設格式為 https://<帳號>.github.io/<儲存庫名稱>/，也可綁定自訂網域）：

確保專案根目錄或指定資料夾（如 /docs）中有入口檔案 index.html。

前往 GitHub 儲存庫的 Settings（設定） ＞ 左側選單 Pages。

在 Build and deployment 的 Source 選擇 Deploy from a branch。

選擇發佈分支（通常為 main）與資料夾（/ (root) 或 /docs），點擊 Save。

等待數十秒至數分鐘部署完成後，Pages 頁面會顯示可公開存取的網址。

### 三、網頁製作(5%)
1. 運用AI由規格製作網頁的流程為何？
   Ans:需求定義與規格撰寫： 確定網站主題、目標客群、頁面數量與核心功能，並請 AI 整理成清楚的網頁規格書與檔案結構。

建立專案與目錄： 在本地建立專案資料夾（如 index.html、pages/、css/、js/、images/），並開啟 VSCode。

生成骨架與樣式： 讓 AI 依規格產出各頁 HTML 結構與 CSS 樣式表，先完成版面配置與響應式設計（RWD）。

加入互動與內容填充： 補充實際文字、圖片素材，並讓 AI 協助撰寫選單切換、表單驗證或篩選等 JavaScript 互動功能。

測試、除錯與微調： 透過 Live Server 在瀏覽器測試各頁面連結、RWD 斷點與 Console 錯誤，將問題回饋給 AI 修正。

版本控管與發佈： 使用 Git 提交版本並推送至 GitHub，再透過 GitHub Pages 發佈成線上網址。
